# RFC 0002: Herald Protocol

**Category:** Trust  
**Status:** Implementation Candidate (v0.9)  
**Date:** 02026-01-19  

## Abstract

Herald is a protocol for the immutable attestation of state. It defines a standard format for recording the existence of a specific byte sequence at a specific logical path and physical time.

Herald is a passive, append-only format. It does not define transport, retrieval, or verification mechanisms. It assumes a "write-ahead" model where the primary operation is appending a fixed-width, 128-byte record to a linear archive.

This archive can then be kept "in the clear", as it contains no legible information for an adversary. Up to the most-recent checkpoint, you can trust your worst enemy's copy of the index that attests to your private repository's source code.

## 1. Record Format

The fundamental unit of Herald is the **Record**. It is exactly 128 bytes long, aligned to 64-byte boundaries.

All multi-byte integers **MUST** be encoded in **Network Byte Order** (Big Endian).

### 1.2 Field Semantics

#### Timestamp (32 Bytes)

A 256-bit unsigned big-endian integer in **Q128.128** Fixed-Point format.

The field is composed of exactly two 128-bit integers (High/Low):
- **Offset 0-15 (Seconds):** The whole number of TAI64 Seconds (Unsigned).
    - **Range:** Approximately 10^31 years.
- **Offset 16-31 (Fraction):** The fractional second.
    - **Resolution:** Approximately 10^-38 seconds.

#### PathHash (32 Bytes)

The **BLAKE3** hash of the canonical **Path**:
- **Encoding:** Paths **MUST** be strictly 7-bit US-ASCII (0x00 - 0x7F).
- **Canonicalization:** Paths **SHOULD** be normalized prior to hashing. Redundant segments (e.g., `./`) **SHOULD** be removed. The user's choices in this regard are their own.
- **Protocols:** Protocol prefixes (e.g., `https://`, `git+ssh://`) **SHOULD** be omitted unless they are strictly required to disambiguate the resource.
- **Case:** Paths are case-sensitive. `example.com/docs/One` and `example.com/docs/one` are distinct Paths.

#### AttestedHash (32 Bytes)

The **BLAKE3** hash of the **Blob** (exact byte sequence) observed:
- **Scope:** This is the hash of the data itself. It does not include transport headers, filesystem metadata, or the Path.
- **Empty:** An empty payload (0 bytes) is represented as `BLAKE3("")`.

#### Reserved (32 Bytes)

This range **MUST** contain zeroes (`0x00...00`):
- **Purpose:** Reserves space for future enhancements.
- **Padding:** Ensures the record aligns to 128 bytes for current-hardware pragmatism.

## 2. Checkpointing

To allow for efficient verification and anti-entropy without scanning the entire log, Herald supports  **Checkpoint Records**.

### 2.1 The Checkpoint Record

A Checkpoint is a standard 128-byte Record with specific values:

- **PathHash:** `BLAKE3("herald:checkpoint")`
- **AttestedHash:** The **Merkle Root** of all records appended since the previous Checkpoint.
- **Timestamp:** The time the Checkpoint was generated.
- **Reserved:** All-zeroes indicates a checkpoint implemented as-per this herein-documented Herald version.

### 2.2 Archive Maintenance

Herald distinguishes between **Pending** and **Canonical** states of an Archive:
- **Pending:** A sequence of records ending without a Checkpoint. This is the natural state during ingestion (e.g., `cat new_records.bin >> archive.bin`).
- **Canonical:** A sequence of records where the final record is a Checkpoint.

**Constraint:** A Valid Herald Archive **MUST NOT** contain a sequence of more than **1,024** records without a Checkpoint.

- Writers **MAY** enforce this limit.
- Archivers (maintenance tools) **MUST** detect this condition and append a Checkpoint to transitition from Pending to Canonical status.

## Appendix A: Timestamp Conversion

To convert a standard TAI64N timestamp (Seconds + Nanoseconds) into a Herald "Q128.128" timestamp:

**Formula:**
```math
HeraldTime = (Seconds \ll 128) \lor \left\lfloor \frac{Nanoseconds \times 2^{128}}{10^9} \right\rfloor
```

**Implementation ("Pseudocode"):**
```ruby
# 2^128 as a constant:
Q128 = 340_282_366_920_938_463_463_374_607_431_768_211_456

def seconds_and_nanos_to_herald(tai_seconds, tai_nano)
  # Fractional component via integer division:
  fraction = (tai_nano * Q128) / 1_000_000_000
  
  # Pack as 256 bits:
  (tai_seconds << 128) | fraction
end
```
